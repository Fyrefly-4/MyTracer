## 实现对应

| 体验问题 | 本轮实现 |
| --- | --- |
| 未完成输入和工作上下文易丢失 | 行动与例行记录草稿及其记录连接在当前应用会话内跨页面保留；返回时恢复已填内容，并提供明确的“放弃草稿”。若连接失效，保留输入并允许重新开始记录。目标、行动、例行、Recovery、Progress 筛选和 Data 所选记录也保留会话期上下文。 |
| Today 日常路径层级不清 | 今日重点与今日例行置于首屏，其次是今日意向；其它行动折叠为候选区，并可直接选择重点或意向。行动详情持续说明它与目标当前下一步、今日重点/意向的关系，所有关系变化仍由用户主动选择。 |
| Recovery 到下一步行动衔接弱 | Recovery 先展示当前可继续事项、最近真实记录、已有理解和未解决困惑，再提供选择/创建下一步；当前下一步可经确认加入今天并直接继续。暂停、结束及整理操作移至独立管理区，确认仍保留。 |
| 历史记录难浏览维护 | Progress 将行动与例行合并为按时间排序的统一记录流，并保留目标/日期筛选；每条记录可直达 Data。Data 默认先展示可按类型、目标和日期筛选的记录浏览器，只编辑当前选中记录；补记、导出和永久删除降为按需展开工具。 |
| Routine 偏创建优先 | Routine 默认先展示已有列表及选中详情，记录入口早于编辑管理；新建表单按需展开，会话内恢复所选例行及未保存记录草稿。 |
| 文案、操作层级与视觉信任 | 清理 Provider、上下文等内部表达，统一“已确认的理解”“尚未解决的困惑”“最小行动”等用户语言；普通确认使用绿色、暂停/重新安排使用提醒色、结束和永久删除使用危险色，并补充窄窗布局规则。 |

会话期恢复不跨应用重启，也不将草稿写入 SQLite。记录事实、行动生命周期、目标当前下一步和 Today 选择仍是彼此独立的既有产品事实；信息同步展示不触发自动状态变化。
