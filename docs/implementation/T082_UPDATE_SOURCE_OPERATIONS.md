# T082 私有更新源操作说明

本说明对应 [T082 合同](T082_PRIVATE_UPDATE_CHECK_DOWNLOAD.md)和 [EV-T082-001](ACCEPTANCE_EVIDENCE_V0.1.md#ev-t082-001)。应用版本为 `0.1.2`，更新源在构建时固定为 `Fyrefly-4/MyTracer` 的私有 GitHub Releases 稳定通道。T082 只提供用户主动检查和明确确认后的校验下载；安装、退出协调和正式发布分别属于后续任务。

## 首次配置

1. 由仓库所有者准备仅能读取此私有仓库 Release 及资产的凭据，并通过受控的本机凭据管理方式向启动 MyTracer 的进程环境注入 `MYTRACER_UPDATE_TOKEN`。不要把 token 写入命令历史、仓库、配置文件、SQLite、截图、日志或证据；不要用 `GH_TOKEN`、发布 token 或 AI Provider key 代替。
2. 完全退出 MyTracer，再从已获得该环境变量的会话启动应用。Main 仅在启动时读取 token；已运行的进程不会自动读取后来变更的值。先确认使用的是预期的 `0.1.2` 安装包及受控测试环境，不覆盖现有默认用户数据。
3. 在“关于与更新”中主动点击检查。没有凭据时应显示未配置；凭据无效或权限不足时应显示鉴权失败，不应误报“已是最新”。只有高于 `0.1.2` 的稳定版本且元数据/预期资产符合校验规则，才会出现可下载候选。点击下载后仍只得到已校验文件，不会执行安装。

本仓库在 2026-09-29 尚无高于 `0.1.2` 的稳定 Release；owner 已批准将真实私有源检查/下载、最终发布包来源/hash 与安装版人工体验交给 T084，当前均保持待验证。创建 Release、配置 Actions secret 或发布资产均需单独授权。

## 轮换与撤销

- 轮换时在受控凭据来源替换只读 token，完全退出并重启应用，使 Main 读取新值；确认旧 token 已由凭据发行方撤销。不要把旧值或新值写入问题单或测试日志。
- 撤销时先在凭据发行方撤销 token，再清除启动进程的 `MYTRACER_UPDATE_TOKEN` 来源并重启应用。无凭据只影响更新检查/下载；业务数据操作和导出仍应可用。
- token 失效、断网、超时或下载校验失败后，先核对来源权限和受控测试资产；可以重试检查或下载，但不得绕过版本、来源或 hash 校验，也不得把不可信文件当作已下载结果。

## 网络、完整性与签名

- 主动检查和下载会连接固定的 GitHub 私有 Release 服务。网络服务及其资产分发方可能看到连接 IP、时间和常规传输元数据；远端简短说明在界面中按纯文本处理。
- 下载结果要与预期版本、资产名及 Release 元数据中的 SHA-512 一致。用于实测的包还应单独记录来源 revision、资产名、版本与 SHA-256，避免将不同构建的 hash 混用。T082 不提供来源选择器，也不会自动检查、自动下载或在退出时安装。
- 当前 Windows x64 NSIS 包未签名；Windows 可能显示未知发布者或其他保护提示。不要关闭系统安全保护来完成测试。下载成功不证明安装成功，T083 的确认安装与安全退出仍需单独验证。
