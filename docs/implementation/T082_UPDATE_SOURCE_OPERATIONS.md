# T082 私有更新源操作说明

> 下文 0.1.2 与仅下载边界是 2026-09-29 的 T082 历史快照。当前 0.1.4 已含明确确认安装；请结合文末更新使用。

本说明对应 [T082 合同](T082_PRIVATE_UPDATE_CHECK_DOWNLOAD.md)和 [EV-T082-001](ACCEPTANCE_EVIDENCE_V0.1.md#ev-t082-001)。应用版本为 `0.1.2`，更新源在构建时固定为 `Fyrefly-4/MyTracer` 的私有 GitHub Releases 稳定通道。T082 只提供用户主动检查和明确确认后的校验下载；安装、退出协调和正式发布分别属于后续任务。

## 首次配置

1. 由仓库所有者准备仅能读取此私有仓库 Release 及资产的凭据，并通过受控的本机凭据管理方式向启动 MyTracer 的进程环境注入 `MYTRACER_UPDATE_TOKEN`。不要把 token 写入命令历史、仓库、配置文件、SQLite、截图、日志或证据；不要用 `GH_TOKEN`、发布 token 或 AI Provider key 代替。
2. 完全退出 MyTracer，再从已获得该环境变量的会话启动应用。Main 仅在启动时读取 token；已运行的进程不会自动读取后来变更的值。先确认使用的是预期的 `0.1.2` 安装包及受控测试环境，不覆盖现有默认用户数据。
3. 在“关于与更新”中主动点击检查。没有凭据时应显示未配置；凭据无效或权限不足时应显示鉴权失败，不应误报“已是最新”。只有高于 `0.1.2` 的稳定版本且元数据/预期资产符合校验规则，才会出现可下载候选。点击下载后仍只得到已校验文件，不会执行安装。

本仓库在 2026-09-29 尚无高于 `0.1.2` 的稳定 Release；owner 已批准将真实私有源检查/下载、最终发布包来源/hash 与安装版人工体验交给 T084，当前均保持待验证。创建 Release、配置 Actions secret 或发布资产均需单独授权。

## 轮换与撤销

- 轮换时在受控凭据来源替换只读 token，完全退出并重启应用，使 Main 读取新值；确认旧 token 已由凭据发行方撤销。不要把旧值或新值写入问题单或测试日志。
- 撤销时先在凭据发行方撤销 token，再清除启动进程的 `MYTRACER_UPDATE_TOKEN` 来源并重启应用。无凭据只影响更新检查/下载；业务数据操作和导出仍应可用。
- token 失效、断网、超时或下载校验失败后，先核对来源权限和受控测试资产；可以重试检查或下载，但不得绕过版本、来源或 hash 校验，也不得把不可信文件当作已下载结果。

## 网络、完整性与签名

- 主动检查和下载会连接固定的 GitHub 私有 Release 服务。网络服务及其资产分发方可能看到连接 IP、时间和常规传输元数据；远端简短说明在界面中按纯文本处理。
- 下载结果要与预期版本、资产名及 Release 元数据中的 SHA-512 一致。用于实测的包还应单独记录来源 revision、资产名、版本与 SHA-256，避免将不同构建的 hash 混用。T082 不提供来源选择器，也不会自动检查、自动下载或在退出时安装。
- 当前 Windows x64 NSIS 包未签名；Windows 可能显示未知发布者或其他保护提示。不要关闭系统安全保护来完成测试。下载成功不证明安装成功，T083 的确认安装与安全退出仍需单独验证。

## 正式个人使用方案（2026-10-06 owner 已批准）

本节是长期使用的部署与维护约定，不是部署完成记录。Owner 在审阅生产方案后回复“同意”。正式凭据创建、替换、撤销及下面的本机验收尚未报告完成；此前临时测试凭据的成功不替代这些步骤。方案沿用现有私有源、主动更新和本机环境变量方式，不修改程序或新增凭据存储能力。

### 首次正式配置

1. 在 GitHub 的 Settings → Developer settings → Personal access tokens → Fine-grained tokens 中创建正式使用专用 token，例如命名为 `MyTracer personal update`。只选择 `Fyrefly-4/MyTracer`，设置 Contents 为 Read-only，其他权限不主动增加；平台自动附带的 Metadata read 保留。不要复用开发、发布或 AI 凭据，也不要把 token 内置到安装包。
2. 有效期采用 180 天；如账户策略要求更短，以实际允许期限为准。自行设置到期前 14 天的提醒。本节不创建提醒服务。维护记录只保存名称、用途、授权仓库、权限、创建/到期日期和轮换日期，不保存密钥正文。
3. 由 owner 本机操作，在 Windows“编辑账户的环境变量”中设置当前用户的 `MYTRACER_UPDATE_TOKEN`，用新值替换原测试值。不设置系统级变量，不把值写入命令、脚本、文档、聊天、截图或日志。用户环境变量可持久使用，但不是加密保管方案；同一用户运行的程序及继承该环境的进程可能接触到它。
4. 完全退出 MyTracer，注销并重新登录 Windows，从开始菜单或正常快捷方式打开应用。在“关于与更新”中检查；预期显示当前稳定版或可用新版，不出现未配置/鉴权失败。Main 只在启动时读取值，单纯重新打开面板不生效。
5. 确认新值可用后，在 GitHub 撤销原测试 token。核对原值是否还有其他用途；如有，先拆分凭据用途再撤销。随后重启电脑，从正常入口再检查一次，确认正常业务记录和导出仍可使用。无需为这次检查重复安装同版或制造新 Release。

Contents read 是读取 Release 所需的仓库权限，也允许读取所选仓库代码，并非仅下载权限。目前仅 owner 个人使用接受此边界；不向其他用户分发 owner 的 token。权限依据：[GitHub token 管理](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)与 [Release API](https://docs.github.com/en/rest/releases/releases)，查阅日 2026-10-06。

### 日常轮换、失效和泄露

- 到期前：创建下一枚同范围只读 token → 替换本机值 → 完全退出、注销/登录并检查 → 确认可用后撤销旧值。轮换不改变安装位置和业务数据。
- 已过期或撤销：更新不可用不等于软件不可用；继续正常使用，补配新凭据。鉴权失败不能记为“已经最新”。
- 疑似泄露：先在 GitHub 立即撤销，再替换本机值并重启；检查相关账户访问情况，不等待新值验证后才撤销泄露值。
- 不再使用更新：撤销 GitHub token，删除本机环境变量并注销/登录。不要因更新凭据失效卸载应用或清空数据。

### 正式更新源与备用安装

当前客户端固定访问上述私有仓库；从本方案生效起，其稳定 Release 只用于经批准验收的日常安装版本。未验收测试包保留为 Actions 候选产物，不进入稳定更新源。既有 `v0.1.4` 保留演练身份、tag 和原始资产；首次正式发布使用更高版本，不覆盖它，也不将演练重写为正式 accepted-main 发布。

正式安装包从本库经 owner 批准发布的私有 Release 获取；随包保留版本、校验值、来源和简明更新说明。Actions 候选产物不是面向日常使用的正式安装来源。客户端 token 与发布 job 的权限分离，发布操作见 [T084 发布说明](T084_RELEASE_OPERATIONS.md)。

更新服务不可用时，由 owner 通过 GitHub 网页账户取得已验收完整安装包并核对校验值；退出应用后，选择原安装位置进行覆盖安装，不先卸载、不删除应用数据。当前安装目录由 owner 报告为 `D:\MyApps\MyTracer`；它不代表业务数据目录。网页同样不可达时可继续用旧版，等恢复后再更新；不可使用来源不明的替代包或关闭系统保护。

坏版本由 owner 暂停继续推广并评估停止推荐的处置；具体 Release/feed 修改须单独授权，不由 Agent 自动执行。保留可追溯记录，发布更高修复版，不覆盖同版本、不自动降级。安装失败先记录版本、界面错误和结果，不复制密钥或业务数据到问题单；人工修复只使用经验证的同版或更高兼容完整包，不能假定任意旧包均可回退。

### 数据与信任边界

首期仅发布不改变数据库结构的兼容更新。重要更新前可使用现有导出留存数据；导出不等于已具备导入或一键恢复。未来数据库结构更新需要另行批准一致性备份、迁移失败和恢复方案，不通过现有更新器默认放行。

当前 Windows 包仍未签名；校验值用于检查完整性，不替代发布者签名。保留未知发布者/系统拦截的说明，不关闭 Windows 安全保护。账户应保留可用的登录与恢复途径，以便 token 或网络失败时仍能人工获取可信安装包。

Windows 凭据管理器或加密存储、独立私有分发仓库、多用户授权、代码签名及自动数据恢复均属后续独立改进。当前程序不会直接读取凭据管理器；仅将 token 放入那里不能完成配置。更换固定源需改程序/发布流程并验证来源版到新源的过渡。
