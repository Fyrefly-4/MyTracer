# 更新与凭据维护

适用于当前 Windows x64 更新源。当前客户端使用公共免密钥更新；旧客户端过渡见下文。应用只在用户主动检查、确认下载和确认重启安装后执行相应操作；更新不可用时，核心业务与导出仍可使用。

## 公共客户端与旧版过渡

新版固定使用 `Fyrefly-4/MyTracer` 的公共 GitHub Releases，不读取或传入 `MYTRACER_UPDATE_TOKEN`，也不使用 `GH_TOKEN` / `GITHUB_TOKEN`。无需配置更新密钥；机器上残留无效旧 token 不影响新版更新。没有私有 provider 回退或自选远端入口。

已安装的旧版代码不会因仓库公开而改变：旧客户端仍需有效的原只读 token 走旧链路，或者从项目正式 Release 手动覆盖安装一次包含本改动的新版。保持原安装范围、安装位置和 Windows 用户，先退出应用，不先卸载、不删除数据。不要安装较低版本或假定任意版本可回退。

本次不读取、修改或撤销用户本机/GitHub 的旧 token。确认所有旧客户端已迁移后，用户可自行检查旧 token 是否还有用途，再决定撤销和清理。发布 GitHub App / Actions 凭据继续用于发布，不属于客户端读取更新的凭据，不应删除或打进安装包。

## 检查、下载和安装

1. 从正常入口启动，在“关于与更新”主动检查。客户端固定访问本项目 GitHub Releases 稳定通道，不提供分发源选择器。
2. 有可用新版时确认下载。候选版本、资产、来源与 hash 校验失败时不安装，不绕过校验。
3. 保存或明确放弃未保存输入，处理尚未确认的 AI 建议，再点击“确认重启安装”。草稿保护阻止安装时先处理提示；下载成功不等于安装成功。
4. 完成可见的原生 NSIS 安装向导。新版安装器仅在更新标记和原安装范围／路径记录明确一致时跳过范围、目录页；记录缺失或冲突时仍需核实选择，不猜测安装范围。详见[安装器说明](../../build/installer/README.md)。保留同一安装与数据位置。新版启动后检查版本、既有记录和导出，完全退出并重开确认持久化。

当前应用不会自动检查、自动下载或因普通退出而自动安装。当前包未签名；Windows 可能显示未知发布者或保护提示，hash 校验不替代发布者签名，不关闭系统安全保护。

## 更新失败与备用安装

- 公共更新源拒绝访问：检查网络或服务限流，稍后再试；新版无需添加 token。旧版凭据失败可使用上文手动覆盖路径。
- 断网、超时或下载校验失败：保留旧版，恢复连接后重新检查或下载；不把不可信文件当作已下载结果。
- 安装失败：记录版本、界面错误和实际结果；关闭数据库后安装失败若应用保持锁定，按提示重启，不继续写入。手动修复只使用经验证的同版或更高兼容完整包，不能假定旧包均可回退。
- 更新服务不可用：从项目正式 Release 取得完整安装包，核对来源、版本和校验值；退出应用后在原安装位置覆盖安装，不先卸载、不删除数据。安装目录与业务数据目录不同。网页也不可达时继续用旧版，等待恢复。
- 已发布坏版本：保留来源和处置记录，用更高修复版处理；实际暂停推荐或修改 Release/feed 需另行授权，不覆盖同版本或自动降级。

Actions 候选产物用于审核与测试，正式安装来源须是项目已发布的正式 Release。历史演练资产与首次接入背景见[发布维护](RELEASE.md#首次接入与历史基线)。

## 数据与信任边界

首期更新保持数据库结构兼容。重要更新前可导出留存，但导出不等于自动导入或一键恢复；数据库结构更新须另行批准一致性备份、迁移失败与恢复方案，不能由现有更新器默认放行。

主动检查和下载连接 GitHub 及资产分发服务，服务方可能看到 IP、时间和常规传输元数据。公共下载无需 GitHub 登录。分发源变更、签名和自动恢复属于独立改进。

## 校验与验证范围

锁定的 electron-updater 6.8.10 公共 provider 请求本仓库 `releases.atom`、`releases/latest` 和 stable tag 下的 `latest.yml`。白名单仅允许这些确切路径、版本对应的 x64 完整安装包及既有可信 GitHub 资产 CDN；禁用差分下载与 web installer。客户端校验 stable 版本与 `v版本` tag、唯一安装包名称、完整 SHA-512，并在确认下载时重新检查候选；下载后和安装前重新校验文件。HTTPS/hash 不等于代码签名，也不解决 SmartScreen。

合成测试覆盖无 token、残留无效 token、真实公共 provider 的请求路径/无鉴权头、候选变化及损坏文件；这些测试不下载真实安装器。旧私有客户端到新版的真实 Windows 安装过渡、公共下载到原生 NSIS 安装和数据保留仍需隔离环境人工验收；不能将常规 CI 的离线更新测试视为已完成。现有 installed-update 测试保留显式隔离前置条件，旧 token 输入改为可选，仅供旧客户端过渡使用。
