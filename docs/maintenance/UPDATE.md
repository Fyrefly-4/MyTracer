# 更新与凭据维护

适用于当前 Windows x64 更新源。发布仓库可为 public 或 private；当前客户端仍要求本机有效的 `MYTRACER_UPDATE_TOKEN`，不会因仓库公开自动改为匿名更新。应用只在用户主动检查、确认下载和确认重启安装后执行相应操作；更新不可用时，核心业务与导出仍可使用。

## 凭据配置

1. Owner 在 GitHub Settings → Developer settings → Personal access tokens → Fine-grained tokens 创建个人更新专用 token。只选择 Fyrefly-4/MyTracer，Contents 为 Read-only，保留平台附带的 Metadata read，不主动增加其他权限。不复用开发、CI 发布或 AI 凭据，也不把 token 内置到安装包。
2. 沿用已批准的有效期 180 天；账户策略要求更短时以实际期限为准。自行设置到期前 14 天提醒。维护记录只保存名称、用途、仓库、权限、创建/到期和轮换日期，不保存密钥正文。
3. 在 Windows“编辑账户的环境变量”设置当前用户的 `MYTRACER_UPDATE_TOKEN`。不设系统级变量，不把值写入命令、脚本、文档、聊天、截图或日志。用户环境变量可持久使用，但不是加密保管方案；同一用户运行的程序及继承该环境的进程可能接触到它。
4. 完全退出 MyTracer，注销并重新登录 Windows，从正常快捷方式启动。在“关于与更新”主动检查；应显示最新状态或可用新版，而非未配置或鉴权失败。Main 只在启动时读取值，重新打开面板不会更新凭据。
5. 确认新值可用后撤销原测试 token；如旧值还有其他用途，先拆分。重启电脑，从正常入口复查更新、业务和导出，无需为凭据检查重复安装同版或制造 Release。

Contents read 同时允许读取所选仓库代码，并非只有下载权限；当前仅 owner 个人使用接受此边界，不向其他用户分发 owner token。程序不直接读取 Windows 凭据管理器，仅将 token 放在那里不能完成配置。该方案来自原更新源操作记录；历史批准、完成回报和未执行风险见[验收证据](../implementation/ACCEPTANCE_EVIDENCE_V0.1.md#ev-s8-001)。

## 检查、下载和安装

1. 从正常入口启动，在“关于与更新”主动检查。客户端固定访问本项目 GitHub Releases 稳定通道，不提供分发源选择器。
2. 有可用新版时确认下载。候选版本、资产、来源与 hash 校验失败时不安装，不绕过校验。
3. 保存或明确放弃未保存输入，处理尚未确认的 AI 建议，再点击“确认重启安装”。草稿保护阻止安装时先处理提示；下载成功不等于安装成功。
4. 完成可见的原生 NSIS 安装向导。新版安装器仅在更新标记和原安装范围／路径记录明确一致时跳过范围、目录页；记录缺失或冲突时仍需核实选择，不猜测安装范围。详见[安装器说明](../../build/installer/README.md)。保留同一安装与数据位置。新版启动后检查版本、既有记录和导出，完全退出并重开确认持久化。

当前应用不会自动检查、自动下载或因普通退出而自动安装。当前包未签名；Windows 可能显示未知发布者或保护提示，hash 校验不替代发布者签名，不关闭系统安全保护。

## 轮换与撤销

| 情况 | 操作 |
| --- | --- |
| 到期前轮换 | 创建同范围只读 token → 替换本机值 → 完全退出、注销/登录并检查 → 确认可用后撤销旧值 |
| 已过期或已撤销 | 保持正常业务使用，补配新凭据；鉴权失败不能视为“已是最新” |
| 疑似泄露 | 先在 GitHub 立即撤销，再替换本机值并重启；检查账户访问情况，不等新值验证后才撤销泄露值 |
| 不再使用更新 | 撤销 GitHub token，删除本机环境变量并注销/登录；不卸载应用或清空业务数据 |

## 更新失败与备用安装

- 未配置或鉴权失败：检查专用 token 的有效期、仓库与只读权限，以及正常启动进程是否继承新值；不在问题单中提供 token 正文。
- 断网、超时或下载校验失败：保留旧版，恢复连接后重新检查或下载；不把不可信文件当作已下载结果。
- 安装失败：记录版本、界面错误和实际结果；关闭数据库后安装失败若应用保持锁定，按提示重启，不继续写入。手动修复只使用经验证的同版或更高兼容完整包，不能假定旧包均可回退。
- 更新服务不可用：从项目正式 Release 取得完整安装包（私有仓库需要具有访问权限的 GitHub 账户），核对来源、版本和校验值；退出应用后在原安装位置覆盖安装，不先卸载、不删除数据。安装目录与业务数据目录不同。网页也不可达时继续用旧版，等待恢复。
- 已发布坏版本：保留来源和处置记录，用更高修复版处理；实际暂停推荐或修改 Release/feed 需另行授权，不覆盖同版本或自动降级。

Actions 候选产物用于审核与测试，正式安装来源须是项目已发布的正式 Release。历史演练资产与首次接入背景见[发布维护](RELEASE.md#首次接入与历史基线)。

## 数据与信任边界

首期更新保持数据库结构兼容。重要更新前可导出留存，但导出不等于自动导入或一键恢复；数据库结构更新须另行批准一致性备份、迁移失败与恢复方案，不能由现有更新器默认放行。

主动检查和下载连接 GitHub 及资产分发服务，服务方可能看到 IP、时间和常规传输元数据。保持可用的 GitHub 登录与账户恢复途径。凭据加密读取、分发源变更、多用户分发、签名和自动恢复属于独立改进。
