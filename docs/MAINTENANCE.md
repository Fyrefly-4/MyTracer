## 开发与验证

首次启动步骤见 [README](../README.md#本地运行)。以下命令在仓库根目录运行，实际脚本与锁定版本以 `package.json` 和 `package-lock.json` 为准。

| 目的 | 命令 |
| --- | --- |
| 构建 Main、Preload 和 Renderer | `npm.cmd run build` |
| 生成 Windows x64 unsigned NSIS installer 与 unpacked 包 | `npm.cmd run package` |
| 只读格式检查 | `npm.cmd run format:check` |
| 检查代码规范与分层依赖 | `npm.cmd run lint` |
| 类型检查 | `npm.cmd run typecheck` |
| 单元测试 | `npm.cmd run test:unit` |
| 集成测试 | `npm.cmd run test:integration` |
| 构建并运行 Electron E2E | `npm.cmd run test:e2e` |
| 完整应用聚合验证 | `npm.cmd run verify` |

按变更影响面选择本地验证，不因查阅本页要求每次运行全部命令。`verify` 包含 E2E 所需构建，不包含安装依赖、打包、真实安装或 live AI。构建输出位于 `out/`，打包输出位于 `release/`；构建通过不等于人工验收通过。

Electron E2E 需要可启动 Windows 桌面进程的环境。测试使用唯一临时数据库/数据根，日期边界使用 fake Clock，常规 AI 测试使用 fake Provider；不得触碰真实用户数据。风险与测试层级参考[测试策略](architecture/TEST_STRATEGY_V0.1.md)。

## 托管 Windows 验证与手动组合检查

[Verification](../.github/workflows/verify.yml) 的 CI Gate 已运行在 `windows-2025`，无需将它从 Linux 迁移。PR 按变更分类：纯文档做文档与 diff 检查；发布工具变更运行 `verify:release-tooling`；应用源码运行完整 `verify`（含构建与 Electron E2E）。Linux 本地检查可提前发现问题，但缺少 `npm.cmd`、`powershell.exe` 或原生 Electron 环境的结果不能替代 Windows 验证，也不应通过放宽测试掩盖。

同一 workflow 已支持 `workflow_dispatch`。需要验证实验组合时，先记录 main、各源 head、组合提交与冲突处理，再使用有权限的 GitHub Actions 页面选择 **Verification → Run workflow → 目标分支**；该事件强制完整源码验证，不走纯文档或发布工具精简路径。执行后核对 run 的实际 head SHA 与记录一致。普通非 main 分支 push 不会自动触发此 workflow；没有认证入口时应记录“未触发”，不要当作通过。集中一次提交再验证，避免为轮询结果重复启动运行。

[Release](../.github/workflows/release.yml) 的版本协调和发布任务仍使用 Ubuntu，Windows 构建任务负责验证、打包与安装 smoke。无需为了统一平台迁移纯协调任务。测试实验分支应选择 Verification，不能用 Release recovery 代替验证；仓库可见性与额度决定也不自动授权合并或发布。托管检查不等于人工视觉、辅助技术或本机体验验收。

[Installer validation](../.github/workflows/installer.yml) 在应用源码、安装器、打包依赖/配置及相关冒烟测试变更时运行：编译安装包后执行 `test:package-smoke`，覆盖 unpacked 应用、隔离 NSIS 安装、安装后启动及卸载。更新检查对真实打包 provider 的 session 显式模拟离线，断言网络错误后核心读取仍可用，不依赖公共 GitHub 的实时状态；公共元数据与无 token 请求合同由合成集成测试覆盖。这不替代真实跨版本升级验收。

CI 阶段计时、合成 Electron 失败证据和复验约定见 [CI 诊断维护](maintenance/CI_DIAGNOSTICS.md)。

新 [Focused Electron 工作流](../.github/workflows/electron-focus.yml) 提供固定 Data 阅读／内容草稿测试组的 Windows 手动入口；使用方法和“聚焦通过不等于 CI Gate”的边界见 [CI 诊断维护](maintenance/CI_DIAGNOSTICS.md#bounded-windows-focused-entrypoint-next-batch-after-158)。

## 聚焦 UX 检查与环境边界

在已安装锁定依赖、可启动桌面进程的 Windows 环境，复用现有测试即可做小范围冒烟检查，无需新建启动脚本。例如：

```powershell
npm.cmd run build
npm.cmd run test:e2e:run -- tests/e2e/shell.e2e.test.ts tests/e2e/review-summary.e2e.test.ts
```

第一条更新构建产物；`test:e2e:run` 本身不构建。上述三个用例覆盖壳层隔离与基本导航、合成周期事实以及跨周边界，不替代全量 E2E 或人工体验检查。新增实际 UX 探针应复用 [临时数据根](../tests/support/temporary-test-root.ts) 与 [最小 Electron 环境](../tests/support/electron-environment.ts)，保留清理逻辑，使用合成资料；不要复用开发或真实用户的数据目录。

| 环境／检查 | 可以据此报告 | 仍不能据此报告 |
| --- | --- | --- |
| Windows CI 的 Electron E2E | 日志所列提交、用例与实际 UI—IPC—持久化行为通过 | Windows 本机字体、MicaStrong、触控板及辅助技术人工验收通过；未运行的安装包测试通过 |
| 浏览器中的 Renderer 预览或替身接口 | 对应资料、尺寸与缩放下的排版、焦点及前端交互观察 | 真实 Electron／Preload／IPC／SQLite 连通、保存与重启可靠性 |
| Linux 中实际启动的 Electron | 已执行的界面和应用流程；须同时注明显示后端及沙箱配置 | Windows 原生材质／系统窗口行为，或仅凭窗口打开就认定安全配置正确 |

云端 Linux 的启动条件须分别核对：缺少 X server／`DISPLAY` 是显示后端问题；改用 headless 后仍可能因宿主沙箱配置失败。锁定版本的 Playwright Electron 启动器在 Linux 默认会加入禁用沙箱参数，因此“没有手动传入该参数”不等于启用了沙箱。要求保留沙箱的探针应显式设置 `chromiumSandbox: true`，核对实际启动日志和宿主支持；无法启动时记录具体错误并停止，不通过禁用沙箱或修改宿主权限绕过。

当前仓库没有统一的、已验证保留沙箱的 Linux headless UX 冒烟入口。上述 Windows 命令不是跨平台启动承诺；Linux 中将 `npm.cmd` 换成 `npm` 也不会补齐显示、沙箱或发布测试的 Windows 工具依赖。环境启动失败应与产品断言失败分别记录，不能笼统写成“E2E 已坏”或“E2E 已通过”。

报告截图时附上实际资料、窗口尺寸、缩放、执行环境与代码提交；使用评审者可访问的图片链接，本地文件路径不能充当 PR 截图附件。托管 CI 同时注明 PR head 和日志中的测试合并提交；跳过项与未执行的人工检查保持明确。

## 页面阅读选择

今天、目标和数据页在常规桌面宽度下使用双栏及独立滚动。数据页在窄窗或高缩放时改为上下排列、连续阅读，避免挤压双栏。普通进入页面时，只在当前列表结果（目标与记录含当前分页）内恢复上次查看项；找不到时查看首项。首页等明确链接优先打开指定内容；新建、保存或状态调整的结果保持可见，不被列表刷新抢走。空结果提供新建、补记提示或清除筛选入口。

阅读偏好仅在 Renderer 的 `localStorage` 键 `mytracer.viewed-selection.v1` 保存页面、类型和 ID，不保存正文、草稿或业务数据。重启时校验结构，并由页面查询验证可用性；临时空结果不清除记忆，存储不可用时退回当前会话。自动选择不调用写入命令，创建/编辑/记录草稿及确认操作会阻止自动切换。

例行详情进入或切换时读取当日本地记录状态，读取中或失败不会显示为“未记录”；失败可重试。日期由应用时钟确定，未编辑时在窗口重新聚焦或每分钟刷新；正在填写或恢复的记录保持原捕获日期和输入，跨日保存仍需既有日期确认。今天页继续使用其已读取的例行状态。 例行和今天页对已确认的保存记录提供带发生日期的“查看记录”，直接打开现有数据详情；通过侧栏返回原页保留选中例行和会话输入。正在编辑、状态读取中或失败时不提供该入口；跨日刚保存的入口指向实际保存日期。

### 记录简述与笔记

行动和例行记录支持独立可选简述（500 字以内）和可展开补充笔记。笔记采用轻量 Markdown 阅读，链接/图片只显示文字；编辑和 JSON 保留原文。首页只取简述，缺失则显示事实，不摘取旧备注。升级到 schema 7 / JSON 6 后，旧程序不能直接打开新库；升级前完整备份与回退限制见[兼容说明](architecture/RECORD_SUMMARY_NOTES.md)。

### 继续行动时的说明

#128 A 的核对基线为 `eca4d07`：Today 行动详情原先只在折叠的“编辑与管理行动”中提供说明文本框，记录入口前不可读；首页“去今天继续”同样进入此详情。现在在记录与目标历史之前展示当前已保存的行动说明。240 字以内且至多四行直接显示，更长文字用原生展开控件完整阅读；空说明不占位。这个阈值只控制呈现，不截断保存值。

#174 U2：目标详情也按 240 字／四行的呈现边界处理纯文本说明；长说明默认收起，原生控件可展开全文与收起，短说明直接阅读。切换目标重置展开状态，完整编辑值与现有滚动不变，给当前下一步保留首屏空间。

正文按纯文字保留换行，不解析路径、链接或 Markdown；它不是目标简介、本次记录备注或历史下一步。展开状态按行动保留到会话结束，不保存正文副本，也不增加读取请求。详情栏提供底色、留白与滚动，正文不设固定高度或嵌套滚动；窄窗与缩放沿用 Today 原有滚动归属。编辑入口、记录草稿及数据契约不变。

聚焦回归：`tests/e2e/today-action-description.e2e.test.ts`（继续入口、短/长/空、原文、晚到历史响应、键盘、草稿及 820×600 的 100/125/150% 缩放）；Linux 无法保留沙箱启动时不绕过，交由 Windows CI 执行真实 Electron 用例。

## 数据页阅读与工具

数据页进入后直接显示历史列表与详情，顶部仅保留“补记记录 / 导出 / 更多”。补记在侧抽屉中一次显示一种表单；关闭、取消或切换类型保留本页两种草稿，清空当前草稿与带未保存修改离开数据页均需确认。草稿只在当前页面内存中保留，不新增持久化。导出对话框保留范围说明、保存位置选择及结果反馈；更多中的删除仍需影响预览与最终确认。

历史列表支持[本地字面关键词检索](architecture/HISTORY_LITERAL_SEARCH.md)：检索全部当前保存记录中的标题、备注、下一步、理解、困惑和解决说明，再与筛选条件共同分页；撤销/解决状态明确标示。搜索与筛选、页码在本次应用会话导航返回时保留，明确来源链接优先打开指定记录。

筛选入口显示条件数量，面板内即时应用与清除条件，完成后返回阅读。常规桌面仅列表与详情独立滚动；抽屉和对话框使用统一纸色、24px 内容留白及原生模态焦点约束。验证覆盖合成记录的分页、筛选、编辑、补记草稿、键盘关闭和窗口/缩放布局；自动布局断言不替代人工视觉与辅助技术验收。

## 记录册

复盘页保存后保留已保存的文字供继续编辑，并在保存按钮旁区分未保存、保存中、已保存及无法确认保存结果。继续修改后不再显示旧的保存成功状态；每周期仍只有一份复盘，再次保存更新同一份。复盘不列在数据页的行动／例行记录列表中，可从复盘页“在记录册查看已保存复盘”打开周期起始日所在月份。若还有未保存修改，记录册只显示上次已保存版本，返回复盘后仍保留本次修改。

进展页“更多 → 阅读记录册”及数据页“导出 → 阅读记录册 / 保存 HTML”打开独立主内容阅读页。按记录发生日（复盘按周期起始日）分月，首次打开最新月份，年份目录与下拉框仅列有记录月份；窄窗隐藏目录，保留下拉跳转。阅读月和滚动位置只在本次应用会话保存。

记录册进入或从原记录返回时读取当前保存资料，阅读途中不自动跳动。原记录链接进入现有数据详情，返回恢复来源筛选、搜索、选择和滚动；未保存数据草稿仍需确认放弃。原文保留，当前标题、关联、状态明确标为读取时现状，不伪装成历史快照。

“保存全书 HTML”包含所有月份，使用保存时资料，文件内固定 UTC 导出时间；无需联网或远程字体。与应用共用正文和样式，用户文字统一转义。收录范围说明列出未收录对象、计划及设置等排除项，未有日期记录的对象不会被虚构为历史。完整 JSON 保持独立；HTML 不用于导入或恢复证明。设计、边界和验收见[记录册方案](architecture/RECORD_BOOK.md)。

## 产品与操作边界

保留目标、行动、例行、记录和 AI 确认写入的既有语义。产品范围、依赖、数据迁移及权限变化按当次授权和根 AGENTS 处理；普通维护不创建 Txxx 合同、不激活 Profile、不回写阶段验收账本。

当前包的签名、兼容来源和发布状态需核对确切产物及来源；导出不提供自动导入或一键恢复。执行发布或跨分支集成前实时核对远端，不使用旧部署快照推定当前状态。
