# 未完成记录续写（#157）

用户确认轻量 C，并明确包含新行动第一笔、已有行动继续记录与例行记录。有效输入在对应入口自然恢复，不出现常规自动保存提示、常驻成功徽标或强制恢复对话框。历史记录编辑、目标与例行定义、Review 和助手草稿不在范围内；没有草稿中心、同步、提醒或全局撤销。

## 行为

- 比较实际输入值与初始值。空打开、展开区域、填写后撤回原值不构成需保留内容。选择了不同的结果、时长等也属于输入，不仅保护备注。
- 切页、收起窗口、正常关闭不等于放弃；明确放弃才清除。正式保存成功清除对应输入，不会提前创建记录、更新状态、统计或目标下一步。
- 保存的是原始本地日期。跨日沿用既有日期确认，不自动改成今天。恢复时重新核对关联对象及例行安排／当天记录；变化时说明并要求核对，保存仍经过原有领域验证与同日唯一性约束。
- 对象删除后不悄悄丢弃输入或新建替代对象。在对应页面提供这类异常输入的查看／放弃；不为正常输入增加列表。
- 保存结果未知时冻结有关输入，允许只读核对提交结果后继续。核对不会自动执行写入。首笔保留原有“重试确认同一笔”的固定身份机制。
- 数据页导出说明简短解释本机保留和隐私。仅保留失败、日期／对象变化、提交结果未知等异常需要可见说明。

## 存储与权限

schema 8 新增 `record_continuity` 私有表。开放操作只存版本化加密载荷；主键是稳定操作 UUID，另有修订号与 open/saved/discarded 状态。载荷只包括输入、对象 ID、原日期及校验用摘要，不包含旧窗口 sender、IPC 能力、完整领域对象或凭据。折叠状态不持久化。

加密由 Main 调用 Electron safeStorage；Linux 的 basic_text 后端不能用于输入保护。不可用时不明文降级，保留失败会明确显示，仍可通过正式保存形成正常记录。不能解密的旧输入不会被覆盖；已有资料仍可查看，新增记录入口须先解决读取失败。

Renderer 只通过具体类型 API 操作；Main 校验可信窗口／来源、当前会话能力、字段白名单、类型、长度及修订号。恢复时 Main 从本机可信载荷创建新的窗口能力，保留稳定操作身份，绝不重放旧 capability。未完成内容不进入核心 JSON、记录册、AI 上下文或技术日志。

## 提交与退出

正式命令的原有应用事务嵌套在同一连接的外层事务中。业务事实及所有完成／下一步副作用，与 saved 回执及加密载荷清理一起提交；其中任一失败则整体回滚。回执仅有操作身份、修订和状态，没有正文或旧业务快照。即使用户后来删除正式记录，旧操作也不能重放。

saved/discarded 状态拒绝迟到保留写入；同一开放操作只接受更新修订。空值撤回移除载荷。当前窗口保留提交状态跨组件生命周期，切页再回来不能绕过保存中的输入锁。回复丢失时可查询同一操作状态，不能靠相同正文或“当天存在记录”猜测提交成功。重启后，原子清理确保已提交输入不会恢复；未提交输入仍可填写。

SQLite 启用 WAL 与 FULL synchronous。正常关闭先冻结 Renderer 交互，在下一绘制帧后等待已发送的保留操作，并确认没有未结束的提交。超时、Renderer 无响应或存储失败时，只在明确告知可能损失最近输入后由用户决定是否退出。强杀／断电不保证尚未获得持久化确认的最后输入。

更新安装继续使用原有多次探测、写入 gate、drain 与 seal。实际未提交输入仍阻止安装；空录入表单不误报 dirty。其他编辑及 AI 的安装保护不放宽。新增保留写入走同一 guarded IPC，不绕过安装锁。

## 迁移、备份与兼容

本次迁移已获明确授权；未新增依赖。首次打开旧库、开始迁移前，以 SQLite `VACUUM INTO` 制作同目录独立快照并验证完整性；失败停止升级，不用空库替代。每次尝试使用独立文件，避免复用失败尝试留下的旧快照。新建空库无需快照。迁移自身在事务内执行，失败不留下半张表或错误版本号。

快照命名 `mytracer.sqlite3.before-record-continuity-v8-<UUID>.sqlite3`，保留供人工恢复，不自动覆盖或删除；它包含迁移前的核心资料，保密级别与原数据库一致。它不包含尚未存在的新输入表。若删除核心资料，旧快照仍可能保留旧事实，用户可在应用关闭后自行移走或删除不再需要的快照。本功能没有自动还原流程。

原核心表与导出字段不变：JSON 仍为 v6，验证器兼容 sourceDataVersion 7 与 8；来源版本仍如实为 8。私有输入表和回执均排除。旧应用拒绝更高 schema，不能直接对 schema 8 降级运行。

本机输入持续保留至正式保存、明确放弃或撤回原值；回执不含正文且保留用于拒绝旧操作。删除不等于安全擦除磁盘／WAL／系统备份；系统对 userData 的备份可能含加密文件，不承诺跨机器或 Windows 账户解密。应用不上传这些内容。

## 验证边界

合成 SQLite 场景覆盖三入口重开、加密与导出排除、空值／撤回、修订乱序、丢回执、提交后清理、放弃后迟到写入、事务回滚、对象变化／删除、跨日、例行同日冲突、完成与下一步副作用、迁移前快照和迁移失败。Renderer 会话测试覆盖待写入关闭、失败重试与真实 dirty 语义。

Electron 场景覆盖三个实际入口填写、直接正常关闭、重启无恢复弹窗、恢复原值以及正式保存／放弃后再次重启。现有更新安装测试使用实际输入验证阻断，不再把空打开当作未保存内容。Windows 安装／原生 IME／真实用户理解属于单独验收；源码测试不替代这些观察。
