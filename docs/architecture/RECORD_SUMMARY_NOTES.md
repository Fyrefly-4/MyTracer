# 记录简述与补充笔记（#150）

2026-10-24 用户批准：行动记录、例行记录分别保存可选简述和可选补充笔记。简述是主要文字输入，用一两句话即可，也可留空；允许自然换行，保存上限为 500 个 Unicode 码点（不按 UTF-16 单元计数）。笔记沿用文本框，展开和收起不清空草稿。编辑已有笔记时直接展开。结果、时长、下一步、日期和统计语义不变。

普通记录、新行动第一笔、补记和编辑均写入独立字段。会话草稿包含简述，沿用取消、失败重试、未保存提示及请求归属规则；第一笔的未确认提交仍锁定同一请求重试。没有自动摘要、旧笔记回填或新增 AI 上下文。

首页紧凑展示至多两行简述，缺失时回退到名称、日期、结果等事实，不使用笔记或理解片段。详情、进展、复盘和记录册分别呈现简述与完整笔记。搜索覆盖两者并标明命中字段；只有简述的行动也属于可展开文字记录。进展和复盘的行动文字仍按需读取，晚到的响应不得替换当前记录。

## Markdown 阅读与安全边界

依赖固定为官方 npm registry 的 `marked@18.1.1`（MIT，Node >=20，无运行时依赖）。实测 npm 包解压大小 518,121 字节；用当前 esbuild 对共享安全笔记模块打包压缩，约 48.4 kB，gzip 14.6 kB。实际应用构建还含自身 UI、React 等，不能把包解压大小当成下载增量。当前项目锁定 Node 24.18.0 / npm 11.16.0；本地验证环境为 Node 24.19.0 / npm 11.9.0，Windows CI 使用锁定工具链。

`src/presentation/record-note.ts` 使用 Marked lexer，随后仅输出封闭的安全 HTML 元素集合；不是自行解析 Markdown。支持标题、段落、列表、强调、引用、行内代码和代码块。所有用户文字统一转义，HTML token 按文字显示；不输出用户提供的标签、属性或可执行代码。链接只显示文字和地址，图片只显示替代文字，不创建 `a`、`img`、外部打开入口或资源加载。无数学、图表、语法高亮、CDN 或远程字体。

简述始终按纯文字显示。笔记原文保存在 SQLite 和完整 JSON；不把渲染 HTML 写回数据库。长笔记按渲染容器折叠，不裁断源文本。代码和长地址允许换行；标题大小限定在笔记容器，记录册的 `dd` 不对 Markdown 元素套用整段 `pre-wrap`。

应用详情与 `src/presentation/record-book.ts` 使用同一安全规则；离线 HTML 在导出时完成 Markdown 渲染。原有 CSP、固定导航脚本与哈希规则不变。阅读不调用写入命令。

## schema 7 / 完整 JSON 6

在 schema 6 上增加 `action_records.summary`、`routine_records.summary` 两个 nullable TEXT 列。迁移没有 UPDATE 旧记录：旧简述为 null，旧备注和其他字段逐字保留。两个 ALTER 与版本更新同属一个事务；任一步失败均回滚。数据库升级后再打开不重复迁移。

完整 JSON v6 要求 sourceDataVersion 7，记录必须含 `summary`（string 或 null），上限同保存校验。note 保留原始字符串。v1–v5 的严格字段白名单和旧形状验证分支继续存在，不能向旧版本偷偷添加 summary，也不提供丢弃简述的降版本导出。

**回退不是原地降级。** main 基线 `a773311` 的旧程序只支持 schema 6，会拒绝 schema 7；旧导出验证器也不接受 v6。不要修改 metadata 版本或删除新列以绕过检查。升级前先关闭应用、确保 SQLite WAL 已正常检查点处理，再保留完整应用数据目录的独立副本；同时保存完整 JSON 便于检查资料。回退到旧程序必须恢复升级前的数据副本到独立位置，升级后新写内容不会出现在该旧副本中，须另外保留新数据库和 JSON。不能用旧程序直接打开新库，也不能承诺两个分支的数据自动合并。

应用当前没有完整 JSON 导入/一键恢复 UI。这里的 JSON 往返验证指序列化、解析和严格结构验证，**不表示已经支持导入恢复**。已验证合成数据库的迁移事务回滚，以及基线旧 migrator 拒绝新库且不写入；关闭数据库后复制的升级前副本可恢复到 schema 6 并保留旧 note 字节。
