# 结束后翻开新一页：关联的新目标

#127 C，经 owner 确认实施。基线为 main `78efa1c`，包含 #145；不启用历史阶段交付流程。

## 实施提案与边界

从已结束目标的详情选择“开始新阶段”，在临时表单中参考、修改或清空旧名称和说明。只有保存才创建新的活跃目标 ID；取消、Escape 或放弃离开不写入。旧目标保持结束。新目标不复制行动、记录、下一步、今日选择或例行，不聚合任何统计。名称可独立修改。

每个目标最多有一个前阶段，同一旧目标允许多个后续阶段；详情仅提供上一阶段与后续阶段按钮。没有编号、树、关系编辑器、恢复终态或重新开启功能。普通新建目标仍保留原流程。记录册继续按真实发生日期及当前关联阅读，不产生“阶段事件”，不移动历史。

## 数据与事务

SQLite v6 在 goals 增加可空 `predecessor_goal_id`，引用 goals.id，删除时置空；旧行值全为 NULL。索引支持后续查询。插入要求前阶段已存在且 ended，禁止自身引用；关系不可重新指定，前阶段有后续时不能改成非 ended。新 ID 只能指向已经存在的 ended 目标，因此正常创建路径不会形成环。迁移与版本写入在同一事务，失败回滚当前迁移。

`goals:create-stage` 为独立、严格校验的 IPC，普通 create 不接受前阶段字段。表单生成一次 UUID 作为新目标 ID，重复提交与重试使用同一 ID；事务内检查已存在的目标是否属于同一前阶段，否则拒绝。成功重试返回已有目标，不覆盖其后来编辑内容。事务内重新读取前阶段；并发删除导致缺失或 SQLite 快照写冲突时不留下新目标。表单保留失败内容供重试或取消；没有新增持久化请求日志或标题快照。

前阶段 ID 随 Goal 持久化、snapshot 和领域映射保留。详情显式提供当前存在的相邻目标视图。AI selector 仍使用原有字段白名单，不加入阶段 ID、前后阶段正文或相关历史；记录、Today、进度查询不沿阶段关系遍历。

## 删除

删除任意目标仍只按原规则处理它自己的内容。前阶段与后续阶段关联全部解除；其他阶段及其数据保留，不重新接到祖先，也不保留被删目标标题。

`detachedGoalStages` 使用 `后续ID|前阶段ID` 表达每条受影响关系，包括被删除目标的入边与出边。该集合进入预览计数、确认指纹与事务内重新校验。删除后从前后 snapshot 重建实际影响，并验证存活后续的前阶段已为空；额外断链或额外删除触发事务回滚。外键是最后保护，不替代预览与核验。

## 导出与兼容

完整 JSON 升为 v5，严格要求 `sourceDataVersion: 6`；Goal 必须显式包含 `predecessorGoalId`（null 或有效 ID），拒绝缺失、非法类型、缺失引用、自引用、环及非 ended 前阶段。保留 v1–v4 各自原有验证合同，旧格式不接受新增 Goal 字段。

旧数据库正常升级只增加空关系列，保留 ID、字段、记录日期与既有关系。旧应用拒绝 schema v6；不支持原地降级或通过改 metadata 伪装降级。若需退回，只能使用升级前独立备份并接受其后修改不在备份中；JSON 导出不是已实现的自动导入/恢复能力。本功能不增加依赖、不操作真实用户数据、不发布安装包。

## 表面与验证（#131）
