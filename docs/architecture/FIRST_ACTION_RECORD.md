> 后续演进：#157 已批准三类新增记录跨重启续写；现行持久化、退出及提交核对边界见[未完成记录续写](RECORD_CONTINUITY.md)。下文“仅会话／无迁移”描述原首笔实现范围。

## 入口与事实

Today 的“记一笔”与面向未来的“新建行动”并列，沿用既有双栏与奶白临时操作面。用户填写做过的事、真实分钟（包括 0）或明确未知、记录结果，以及可选备注/目标。结果和生命周期各自必选、没有默认值：本次达到预期仍可继续保留，部分推进也可明确结束行动。保存不写 Today selection 或目标 currentNextActionId。

已有行动通过选择器打开原对象及原记录面板，不因新入口另建同名对象；新标题与可记录行动同名时提示核对。例行、历史补记、已结束对象及原深入记录维持既有入口。目标仅在创建时可选，没有以后重归属的承诺。

## 原子性与兼容方案

- beginFirst 仅分配 Main 所有、绑定 sender 的会话能力与行动 ID，捕获本地日期，不写数据库。普通记录和首次记录的能力不可混用。
- saveFirst 只接受列举的字段；目标必须仍然 active。行动和记录在一个 UnitOfWork transaction 内写入，结果读取也在事务内；任何异常整体回滚。不串接两个独立 IPC 写入。
- context ID 同时作为第一条记录 ID（两者不是同一张表）。已存在该记录时返回原提交对应的事实，检查 action ID 匹配，不重复创建、不以重试的新文本覆盖事实。Main 同时保留当前会话的成功回复，随后编辑/删除原事实也不会因旧请求重放而重建对象；新开普通记录不清除首次记录的回复能力。Renderer 同步 busy guard 防双击；首次已提交请求的身份在失败重试时保持。
- IPC 回复丢失时冻结提交内容与放弃按钮，保留原请求并提示重试确认；随后收到 not-found / invalid-transition 表明目标在提交前已不可用，解除锁定以修正或放弃。已提交请求先返回成功缓存，不会因目标后续变化返回这两种错误。validation 在缓存查找前可能拒绝请求，不单凭它、能力失效或持久化错误解除已有的不确定锁定。保存成功后的刷新失败不能还原已提交草稿。跨午夜先询问日期，确认前没有业务写入；已提交的重试先识别原记录，不把它移到新日期。
- 无新增 schema、迁移、依赖、导出格式或跨重启草稿；schema 4 / export v3 完全继承 #133。已有数字/零/null 含义不变。重试识别使用现有记录主键，生命周期能力仅在当前 Main 会话有效；应用重启后查看已保存事实，不恢复旧提交能力。该机制不是独立的永久命令收据或删除撤销机制。

## 草稿和局部布局归属（#131）

begin 回复必须仍由存活组件与当前会话 generation 拥有；离页或新请求后的迟到回复只取消自己的未使用能力，不写回或覆盖新草稿。草稿在 UiSession 内存中保留，收起、Escape、切页返回保持输入；参与退出未保存检查。明确放弃需确认并清除能力与草稿，创建零个行动、零条记录。应用重启不保留草稿，表单明确说明。

原生 dialog 挂到 body，避免继承 Today 日期行的业务布局与颜色；它提供模态焦点约束、奶白 surface、24px padding 与唯一纵向滚动；520px 以下使用 16px 留白。内部 fieldset 不引入第二张卡片或滚动层；输入约束宽度，按钮换行。关闭恢复入口焦点及原页面位置。未改 Home 三目标卡、wordmark、Mica、全局布局或导航层级。

## 验证边界

SQLite / IPC 测试覆盖原子写入、各阶段注入失败与回滚、重试及重开、日期确认、nullable/zero/positive、结果与状态独立、可选目标和无 Today/下一步变更。会话测试覆盖草稿与退出检查。

Electron 场景使用隔离合成资料，覆盖空态、长文、草稿返回/放弃、原有对象路径、失败/丢回复重试、模拟 IME composition Enter、820×600 与 100/125/150% 下实际滚轮及键盘可达。Linux 探针显式保留 sandbox；启动失败不代表这些产品断言通过。Windows 原生 IME、材质和人工视觉验收另行保留待验收；实际运行结果在 PR 中记录。
