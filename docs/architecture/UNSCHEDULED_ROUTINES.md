# 无固定安排例行（#132 C）

本次用户批准：同一 Routine 可在「按星期安排」与「无固定安排」间切换；仍为每日最多一条记录，保留最低行动与四种记录结果。未记录不是失败。非计划日记录继续有效。不增加提醒、配额、频率目标、同步或多条日记录。

## 实施前方案与存储兼容

从 main `4512df04f48c43e634bdde48fb81de9331114aff` 建立分支；#144 记录册已合并。开放 PR 检查未发现本功能重复工作。普通任务未启用阶段 Skill。用户明确允许本功能所必需的最小版本迁移及导出升级。

- Domain、Application、具体 IPC DTO 必填 `arrangementMode: weekly | unscheduled`。weekly 要求非空、无重复的 ISO 星期；unscheduled 要求空星期。缺失、null、未知模式以及不匹配组合拒绝，不把损坏资料解释为无固定安排。
- SQLite v4 → v5：事务内先拒绝没有任何星期行的旧例行，再增加 `routines.arrangement_mode`（NOT NULL，CHECK 两种值，旧值默认 weekly）。不改任何 ID、原字段、日程行和记录。`routine_schedule_days` 是当前安排，历史依据保存在记录的 `plannedForDate` / `plannedForDateBasis`，不是从当前安排反推。
- 切换通过原替换安排命令，在同一事务中保存模式和星期行；不改历史记录。已结束对象仍保持原有内容/安排编辑语义，但不能恢复或新增普通记录。暂停对象不出现在 Today 随时可记列表。
- 完整 JSON 新生成 v4，`sourceDataVersion` 必须为 5；Routine 新增必填模式，验证与日程行组合。原 v1、v2、v3 validator 分支和字段要求保留；v3 仍接受未知行动时长，v1/v2 不接受。旧 validator 曾允许例行没有日程行，这项历史行为不赋予它无固定安排语义，也不是导入转换。v4 不接受旧数据版本；旧格式拒绝模式字段。原 enumValues 保持不变，新模式由 Routine 字段的封闭值检查验证。
- 升级失败的事务回滚、正常升级的字段/记录保全及重复打开由合成测试验证。升级成功后旧版程序会拒绝 v5；没有自动降级 SQL，也不能通过删除模式字段无损降级。需要降级时只能使用升级前另行保留的数据库副本，新版本期间的修改不能因此带回旧版。完整 JSON 是结构化导出，**不宣称可恢复备份**。

## UI 边界（#131）

创建/编辑使用原表单中的「安排方式」选择器，只有 weekly 展示星期选择。模式进入原草稿修订号与异步保存保护。当前安排显示「无固定安排」，不是「每天」或空白星期。

Today 原例行区域末尾提供原生 details/summary「随时可记」，展开后选择活跃无固定安排例行，复用右栏记录面板及原 Routines 手动记录路径。不会自动选取全部无安排例行，也不会把它们加入 plannedRoutines。明确选择或返回上次选择可以恢复该详情。折叠不会清除草稿。

底色与外层留白由原 Today 工作区/例行面板提供；列表使用现有行样式，不加全局覆盖或包装卡片。正常宽度沿用列表/详情各自滚动，窄窗与缩放沿用原页面响应布局。summary 具有原生键盘展开行为；记录表单继续使用原取消焦点恢复、草稿、请求序列与导航保护。

## 投影核查

| 投影 | 处理 |
| --- | --- |
| Today/Home | Today 明确拆分 planned / unscheduled；Home 原计划入口仅使用 planned。无记录不生成义务。 |
| Routines | 名称、最低行动、状态及当前安排可见，手动记录保留。 |
| Progress/Review | 只聚合真实记录和历史 plannedForDate，无计划日分母或 0% 遵守率；未知时长保持 null。 |
| Data/完整 JSON | 原补记、历史修正与历史依据保留；导出升级如上。 |
| 记录册 | 使用真实日期记录及历史计划日依据，不从当前安排补日期；不扩展为完整对象备份。 |
| AI context / stats | 继续由原真实记录事实投影，不新增 AI 权限、原始对象上下文或缺席推断。 |

## 验证与人工检查

合成测试覆盖明确模式、异常组合、旧 weekly、双向切换、历史事实、同日唯一性、非计划日、生命周期、未知时长、JSON roundtrip/旧分支、迁移保全与回滚，以及保存期间更新安排草稿。Windows E2E 新增创建/切换/键盘入口/窄窗缩放；原 Today 延迟请求、取消、跨页与重复选择用例增加 unscheduled 参数。

Linux 不禁用 Electron 沙箱、不改宿主权限；UI 断言需 Windows CI 执行。人工待检查：Windows 字体与材质、键盘/辅助技术、窄窗/高缩放滚动手感、折叠入口是否足够明显、无记录时是否无欠账感。实际命令结果见 PR，不将未运行项列为通过。
