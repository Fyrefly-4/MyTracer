# MyTracer v0.1 关键决定记录

> 状态：随 v0.1 需求基线冻结  
> 日期：2026-08-07  
> 适用范围：Demo v0.1 的产品、架构、实现与验收

## 1. 用途

本文只记录会影响产品语义、架构边界或范围判断的关键决定。完整需求及验收以 [PRODUCT_REQUIREMENTS_V0.1.md](./PRODUCT_REQUIREMENTS_V0.1.md) 为准。

决定状态：

- **已确认**：用户已明确同意，v0.1 不得自行改变。
- **暂定冻结**：为使架构可继续而采用的可逆默认决定；v0.1 按此执行，真实使用后再评估。
- **延期**：明确不进入 v0.1。

## 2. 已确认决定

| ID | 决定 | 影响 |
|---|---|---|
| D-001 | 真实自用是第一优先级。 | 展示性、通用性不得优先于每日使用负担。 |
| D-002 | 核心价值是持续推进并在中断后容易恢复，而不是保持完美连续。 | 不以断签和惩罚作为主反馈。 |
| D-003 | 用户直接理解的核心概念收缩为目标、行动、例行、记录。 | 不新增项目、子任务、领域模块等一级概念。 |
| D-004 | 今日重点由用户最终决定。 | 系统和 AI 只能提供候选。 |
| D-005 | 今日数量采用软性引导，不设置硬上限。 | 交互可以建议少量重点，但不得阻塞用户。 |
| D-006 | 每次行动采用“快速记录 + 可选深入记录”。 | 时间和完成程度是快速层；成果、困惑、下一步可选。 |
| D-007 | 第一版主要进展证据是投入时间、行动次数和用户确认的理解概念。 | 连续天数不得成为主要指标。 |
| D-008 | “有所行动”属于正向事实，但不同于“达到目标”。 | 状态和统计必须保留区别。 |
| D-009 | 未记录不等于未进行。 | 禁止用缺失数据自动推断失败。 |
| D-010 | 主动休息是合法状态，不算失败。 | 复盘与统计不得负面评价。 |
| D-011 | 兴趣与个人时间属于通用非强制意向，不建立专属模块。 | 内容领域不能被写死到一级结构。 |
| D-012 | AI 启动帮助只由用户主动触发。 | 不主动弹出、不后台监督。 |
| D-013 | AI 以温和、非评判式陪伴为主。 | 不羞辱、不制造焦虑、不把休息一律解释为拖延。 |
| D-014 | AI 未经确认不得修改用户真实数据。 | 建议必须可接受、修改或拒绝。 |
| D-015 | AI 是增强能力，不是基础能力。 | AI 失败时记录、查看和管理仍可用。 |
| D-016 | v0.1 采用轻量“目标—行动/例行—记录”路径。 | 通用任务管理能力延期。 |
| D-017 | v0.1 先开发可使用 Demo，再通过 7～14 天真实使用修订需求。 | 不继续为未发生的场景增加需求。 |

## 3. 暂定冻结决定

| ID | 决定 | 真实使用后观察 |
|---|---|---|
| D-101 | 目标状态为活跃、暂停、结束；暂不区分完成和主动放弃。 | 用户是否需要更准确的结束原因。 |
| D-102 | 不建立独立“本周承诺”对象。 | 目标到今天之间是否缺少稳定中间层。 |
| D-103 | 时间允许估算、补记和修改；v0.1 不要求计时器。 | 用户是否经常需要自动计时。 |
| D-104 | 理解成果使用自然语言描述，并由用户确认。 | 最合适的描述粒度和组织方式。 |
| D-105 | 阻力只要求轻量记录，不建立精细原因分类。 | 是否反复出现稳定、值得预设的原因。 |
| D-106 | “今天”按用户本地日期；周期摘要按周一至周日。 | 是否需要调整或配置周起止日。 |
| D-107 | 非计划日发生的例行行动允许记录，并与计划达成分开表达。 | 用户如何理解额外行动。 |
| D-108 | AI 默认只使用当前目标、当前行动或下一步、相关近期记录和本次输入。 | 上下文是否足够且不过量。 |
| D-109 | 不建立跨会话 AI 长期记忆；只有用户确认结果进入核心数据。 | 是否需要保存对话或更长期上下文。 |
| D-110 | 复盘由用户主动进入，不要求通知或主动提醒。 | 用户是否会忘记复盘。 |
| D-111 | v0.1 必须导出完整核心数据；自动导入恢复延期。 | 真实使用是否要求一键恢复。 |

## 4. 延期决定

以下能力不进入 v0.1：

- 通用任务管理、优先级、截止日期、标签和搜索；
- 多层目标、子任务和任务依赖；
- 月历、复杂周历和自动排程；
- 通知、提醒和主动督促；
- 账号、多设备同步和团队协作；
- AI 自动生成整日或整周计划；
- AI 主动介入、跨会话长期记忆和自动用户画像；
- 概念图谱、掌握度评分和完整教学系统；
- 兴趣专属模块、综合生产力评分和复杂统计；
- 自动数据导入恢复；
- 通用插件、动态表单或自定义数据库平台。

## 5. 架构阻塞结论

当前没有等待用户回答的产品语义阻塞项。

架构 Agent 可以决定技术实现、模块边界和交互候选，但不得改变以下冻结语义：

- 四个核心概念；
- 五种例行记录语义；
- 用户决定今日重点；
- 未记录不等于未进行；
- AI 主动触发、最小上下文、未经确认不写入；
- 核心数据独立于 AI；
- 轻量记录与非惩罚恢复；
- v0.1 明确延期范围。

如架构认为某项 MUST 无法成立，应按 [REQUIREMENTS_CHANGE_POLICY.md](./REQUIREMENTS_CHANGE_POLICY.md) 提出变更请求，不得静默改写。
