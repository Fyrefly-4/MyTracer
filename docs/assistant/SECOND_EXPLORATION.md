# Assistant 第二轮探索

本轮来自 #161 的第二轮方向及 2026-10-26 所有者批准，集成目标只为 `assistant/exploration`。三个可用路径优先于完整八故事路线；不改变宿主页面主布局，不增加依赖或 schema 迁移。

## 体验与边界

- 数据页编辑行动／例行记录：`AI 整理笔记` 在编辑器内打开整理卡片。当前笔记自动带入，可对照原文和候选，明确选择填入编辑草稿，再使用原页面的「保存修改」。需要追问时，`带着内容继续对话` 保留同一会话、参考与编辑器桥接。
- 侧栏 `AI 助手`：不选目标也能直接聊。默认不读取业务快照，也不请求模型；只有发送才发起请求。自由对话可以没有来源、没有候选、没有任何业务写入。目标页 `AI 接上上次` 恢复对应本地会话；参考范围中单独授权查询该目标记录。
- 复盘事实列表选择参考后，`AI 回顾选定内容` 使用所选事实，展示来源、查询与程序统计，并允许编辑三字段候选、填入原复盘草稿。正式复盘仍由原编辑器手动保存。

配置留在服务设置；历史和保存模式按需展开。参考显示标题与原文，不展示内部对象 ID／版本哈希。参考选择器由用户展开才读取本机候选列表，勾选或目标范围授权后才允许传给模型。只读工具仍受当前范围、三次调用、八条来源、字符与历史预算约束；截断和省略数量可见，不宣称完整历史。

Main 不再注入 Assistant 业务 writer，旧 `assistant:confirm-write` 接口只返回 unsupported；这不是只隐藏按钮。预览仅校验候选、来源和目标版本。Renderer 填入还核对入口对象、编辑版本、存活状态，成功后禁止重复填入；内容变化需重新整理。历史操作日志继续可读，不重放旧写入。

`conversation/free-chat` 是明确的空上下文标记，不对应业务对象。旧会话 JSON v1 仍可读取，无 SQLite 迁移。保存聊天不等于长期记忆。

第一轮独立的 Today AI 启动帮助仍为旧功能，未纳入本轮 Assistant 通道重构；本轮不扩大它的权限或将它作为新 Assistant 的写入后门。后续统一入口需要单独迁移它的既有产品／测试契约。

## 小故事补充：做了一点，先留下原文

后续小探索从 `9f69c79d0ebd73872345c3e4a113d64c7c16fca0` 出发。检查发现「今天 → 记一笔」原本就能在最终保存时一起创建行动和第一条记录，`beginFirst` 只分配会话上下文，不创建业务记录；缺口是 AI 只接到了已保存记录编辑器，不能帮助首次随手记录。此次复用普通表单，没有新建捕获框架或另一个保存入口。

已实现：先输入原文，选用「AI 整理这段原文」，查看、编辑简述候选，显式填入表单，再自行填写标题、时长／未知、本次结果、行动状态，并点击原来的「保存行动和第一笔」。原文与简述草稿在收起返回后保留，未保存草稿仍不跨重启。简述紧邻原文与 AI 入口，便于检查；不使用 AI 也能走完整保存流程。

此入口只授权当前原文与 Main 所持草稿日期。不加载业务快照，不添加其他来源，不保存 AI 会话。Main 检查 recording context 的窗口所有权、首次记录类型、尚未保存与未取消；候选只允许 `record-summary`。整个表单版本变化、离开编辑器、保存或放弃后，旧结果不能填入。正式保存仍使用原有手动命令、日期确认和重复提交保护。

复现新增故事（浏览器预览或上文隔离原生暂停模式）：

1. 今天 → 记一笔。浏览器 harness 直接点击「记一笔」。不预先创建行动／记录。
2. 输入通用合成原文：`桌面好像全收好了。等等，右边一叠纸没动。大概5分钟？也可能20，没看表。`
3. 点击「AI 整理这段原文」，发送「提炼简述，保留不确定性」。固定模拟候选为 `整理了桌面的一部分；右侧一叠纸还没动，投入时长不确定。`；这只测试交互契约，不证明模型理解矛盾的能力。浏览器 harness 的保存端为假 API，仅供草稿体验；正式手动保存必须在隔离原生 fixture 中检查。
4. 填入草稿。检查原文完整保留，标题、分钟、未知勾选、结果和行动状态没有自动填写；数据库应仍无新增业务对象。
5. 收起再继续，检查输入仍在。手动写标题「合成随手记录：整理桌面」，勾选未知时长，选择推进一部分、继续保留，再手动保存。应仅创建一个 pending 行动及一条 partial、时长 null 的记录，不关联目标或设置下一步。
6. 反例：候选生成后修改原文、标题或其他字段，再尝试填入，应提示重新整理且不覆盖；等待响应时收起／放弃，不能让晚到结果回填。空原文不能发送整理。

原生自动旅程已增加以上草稿到手动保存检查；独立的 `first-action-record` 原生回归仍覆盖丢失保存回执后的同笔重试、跨页面草稿、显式事实与窄窗口可达性。预览未降低 Electron 沙箱要求。

### 产品发现与未实现方向

本轮交付只闭合「已经做过一点 → 零散原文 → 可编辑简述 → 手动事实确认和保存」。它不是任意聊天自动沉淀记录，也不能把未来计划误作已发生事实。原表单还要求为行动命名和选择状态；如果只有模糊感受或未来想法，当前不应强行保存为行动记录。这是现有领域对象的限制，不用模型猜值来掩盖。

后续可用合成反例继续探索两项，尚未实现运行时功能：目标接续应帮助用户理解上次停在哪里、哪些背景缺失，以及这次精力／时间变化，而不只是恢复聊天；回顾应区分相互矛盾的陈述、未知日期和可核实趋势，而不只是给句子挂引用。可比较「仅一条记录」「跨期缺失」「同一事实前后改口」「今天只想聊、不想做计划」等情景。固定响应无法验证这些综合判断，更不能证明真实模型有效；此轮没有为它们增加长期记忆、自动代理或新的工具权限。

## 原生体验后的小批修复（2026-10-27）

基于 #178 已合入的 `7a84127115552e59db5b82ffda521e048cd541cb`，只处理 #161 原生体验评论中的三项：

- 数据页内整理卡片的 anchor 跨满**编辑器内部网格**，不改变宿主 master/detail 双栏。卡片采用 border-box，内部留白缩小；打开时显示标题，候选生成后滚动到候选区，不抢键盘焦点，关闭仍恢复原入口位置。
- 原笔记超过 500 字或 8 行时默认折叠，用户可展开全文；短笔记仍就地显示。生成结果不会重置用户的展开选择，也不改变原文或上下文预算。
- 完成且没有候选时提示「回复完成。」；成功填入用「已填入未保存草稿」，版本校验拒绝后用「内容已变化，候选已过期」，不再合并两种状态。填入成功或过期的候选都不能重复填入；没有新增正式写入通道、持久化状态或接口。

复验仍使用上文隔离 fixture。数据 → 记录 → 编辑，先以短笔记打开整理，检查卡片与编辑区同宽、打开位置；再粘贴约 3000 字／60 行通用合成原文，确认默认折叠、可展开全文、发送后能看到候选与填入按钮。填入后检查成功标签与原文不变，在原编辑器手动保存；另一次生成后先修改简述，再填入，应拒绝并显示过期标签且保留手改。补测停止、切页／关闭返回、未发送输入恢复和零候选自由聊天的「回复完成」。浏览器预览可加 `?editor-grid=1` 模拟 490px 两列编辑区，不能替代父级独立原生体验；真实模型质量仍未验证。
