# E5 · 最近记录到的行动，以日期为主

独立基线：仅实验说明及 CI 配置的 stage `495a787a51f2d5e9c44c02aa7c63520fba84f784`；产品起源 main `a02175e6cf598f08f3c4d053cccb2cf85d42816c`。不叠 E1/E3/E4，不决定其他候选的集成。

## 原观察与变量

RecoveryPanel 的 `.recovery-fact` 标签是“距最近一次实际行动”，主文本是 N 天，发生日期位于小字。domain/recovery.ts 从已保存的所有行动记录及 acted/target_met 例行记录选出最近发生日期；它并不能证明未记录期间没有行动，也不是最后一次输入记录的创建日期。原本截至日和无记录状态都有明确呈现。

只改这一显示区块：标签“最近记录到的行动”，主文本为原 lastRealActionOn，小字保留截至日和“相隔 N 天”。原有 CSS、时间计算、日期来源、顺序、筛选、下一步和其他恢复信息保持不变。没有增加第二组同等显著的大数字。数据字段和 domain/application 完全不动。

无记录仍显示“还没有行动记录”及截至日；当天显示原日期和相隔 0 天。跨月继续直接使用已有日期差。未来日期保留原日期，小字明确“行动发生日期晚于截至日”，而非将负数伪装为已经过去的天数；底层负日期差仍原样返回，不截断、不排除未来记录。这与已有 Goals/Today 对未来日期的显示方向一致，没有定义新的记录状态。

## 假设、代价与否决

假设：先呈现“记录到的”发生日期，可以更准确地提醒这是记录证据，而不是断言其后从未行动；日期也可能更容易对应那一天的经历。尚无用户行为证据，不能仅凭“更温柔”采纳。

反假设：N 天可以迅速比较间隔，日期需要结合截至日判断；间隔降为小字可能让返回者更难识别远近。两处日期并列也可能显得重复，“记录到的”仍可能被误读为创建/补记日期。若 native 对照更难判断距离、误认日期含义，或没有准确性/回忆收益，应保留基线；不通过改统计或额外解释系统补救。

## 极小合成对照

`tests/e2e/recovery-recorded-date.e2e.test.ts` 仅正常 API 写入虚构目标和记录，固定截至日 2026-10-27：当天 2026-10-27 / 0 天，两周 2026-10-13 / 14 天，跨月 2026-09-30 / 27 天，无记录，以及 2026-10-28 / -1 天。未来样本先在 28 日正常补记，再将测试时钟回到 27 日；不是绕过日期校验或篡改 domain。
