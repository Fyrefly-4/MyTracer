## 观察发现（源码证据，不是用户研究）

1. `HomePage.tsx` 顶部始终说“下一步还在这里”，但空库和无下一步分支都存在。多处“小步骤”“做过一点以后”提供泛化引导；个人事实主要在目标摘要及后面的最近记录。假设：准确而有辨识的记录册语气比反复安慰更耐日常阅读。
2. `FirstActionRecord.tsx` 首次记录要求事实、独立结果/行动状态之后，又展示简述、笔记、目标选择才到保存。`TodayPage.tsx` 已有深入折叠，不能将既有分层宣称为新发现。假设：首次记录的可选补充收为一处，可缩短无补充场景的阅读与 Tab 路径。
3. 首次记录和已有行动记录是不同契约。首次结果/行动状态无默认、未知时长显式勾选，不能为轻快而改成默认。现有保存影响、未知与零的区分有直接防误记作用。

## E1 原生反证与最小 refine

父级对首版产品（`d91f9851084d9866e11a5c150d53f8e5b147c097`；测试修正 head `8febb2ed919f38dcabad98ba00d60e858e6809ba` 的产品源码完全相同）进行了原生对照，反馈不能原样采用：实际手工滚动时，热力图与最近记录空态同时出现“没有记录，不代表没有行动”，再加无记录目标卡，共有三个重复槽位。更准确的首页 intro 与记录册意象可以继续比较，但反复声明原则增加了阅读负担。

本次 refine 只改两个槽位：无记录目标卡为“还没有这个目标的记录。”；最近记录空态为“这里按日期留下最近的记录。”。热力图原位置的完整核心语义保持不变，单日无记录说明也保留。相应更新首页读取失败场景的精确文案断言，其余行为不变。待父级短复验，尚不代表最终接受或允许合并。

父级同时报告 E2 的反向取舍：纯事实到保存由 4 次 Tab 减至 2 次，空表单高度 1083px → 843px，但想写一句变成 Tab → Enter 展开 → Tab，操作增加；双层笔记折叠及泛称“已有内容”仍有代价。501 字隐藏错误自动展开聚焦、1160 字长笔记逐字保存已由父级原生实测正确。这些是父级报告的原生证据，本开发容器未重复执行，不扩大为用户研究结论。E2 保留为按场景比较的原型，不追加复杂状态、不合入阶段。
